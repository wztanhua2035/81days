# 《八十一天 DAY 81》v2.1

单人卡牌 / 荒岛生存 / 人物关系 / 智能 NPC / 公共营地 / 个人窝棚网页游戏，可直接部署到 Zeabur。

## v2.1 核心变化

- DAY 1 改为专属沉浸式开场：主角从飞机迫降后的昏迷中醒来，按随机出生地点显示不同环境描述，并提醒玩家寻找食物、淡水并努力等待救援。
- 主游戏界面继续采用手机单屏结构，并重新分配 HUD、场景、文字、行动按钮和底栏所占空间。整页不需要上下滚动；文字较多的剧情区采用局部滚动。
- 放大状态文字、地点标题、行动按钮和场景内人物头像，提高手机端阅读性。
- 人物互动改为更完整的多轮对话。地点图片上同时显示主角和互动对象的大头像，并按人物性格、关系与场景生成更鲜明的说话方式。
- 互动增加 `交易 / 赠送 / 抢夺`：
  - 交易：双方各拿出1件普通可交易物品，NPC自行决定自己拿出的物品；任一方没有可交易物品时不能交易。
  - 赠送：玩家送出1件可交易物品，并提高双方关系。
  - 抢夺：30%概率对方逃脱；70%进入战斗。战斗胜者随机获得败者1件普通物品，败者生命-1。发起抢夺会让双方直接敌对，同时主角与其他幸存者的关系各下降一个档次。
- 关系跨档次变化时弹出醒目提示；达到“生死之交”和首次成为“情侣”时会出现专属对话。
- 玩家抵达有其他幸存者的新地点时，有30%概率由其中一人主动走来触发互动剧情。
- 背包继续为8格。相同的可消耗道具每格最多叠加2个；专属初始道具仍永久持有、不可交易、不可夺取、不可丢弃。
- 探索、人物互动和意外事件有小概率一次获得2—3件物资，只要背包仍有足够空间。
- “我的窝棚”界面显示木材、藤条、零件以及公共营地中的食物和净水数量。
- 新增低概率结构损坏：公共营地设施、个人窝棚或窝棚设施可能因风雨、潮气或意外受损；损坏后效果暂停，使用原建造成本约一半的资源即可修复。NPC也会视智能水平参与修复。
- 普通难度略微放宽属性检定、健康消耗与夜间压力。近似回归模型中六角色平均通关率约53%，较此前略有提升。
- 保留12个日式动漫地点场景、角色动漫头像、60组地点探索事件、60组人物互动、情侣剧情、连续剧情链、大危机、公共营地、个人窝棚、排行榜、管理后台和手机音频解锁。

## 游戏核心流程

1. DAY 1 从飞机迫降后的昏迷中醒来。
2. 每天清晨查看当前地点与同地点人物状态。
3. 决定留在当地或前往其他地点；一旦开始探索或互动，当天位置锁定。
4. 当天可以探索一次，并分别与同地点的每一名其他人物互动一次。
5. 管理背包、公共营地、窝棚和设施。
6. 结束当天，结算 NPC 行动、夜间事件、夜间人物互动、结构损坏、健康与生命。
7. 活到 DAY 81 即获救并进入评分与排行榜。

## 本地启动

需要 Node.js 18 或以上版本：

```bash
npm start
```

游戏：`http://localhost:3000`

管理后台：`http://localhost:3000/admin`

默认管理密码：`818181`，部署后请立即修改。

## Zeabur 部署

1. 将本目录完整上传到 GitHub。
2. 在 Zeabur 新建 Project → Deploy New Service → GitHub。
3. 选择仓库并部署，启动命令为 `npm start`。
4. 不需要数据库，也不需要任何大模型 API。
5. 建议给服务挂载持久化 Volume，例如 `/data`，并设置：

```text
ADMIN_DATA_DIR=/data
```

这样管理后台设置和排行榜在重新部署后仍会保留。

## 存档

v2.1 使用浏览器存档键：

```text
day81_save_v21
```

由于新增物资堆叠、结构损坏、关系弹窗、抢夺后全局关系变化等状态字段，建议部署 v2.1 后重新开始一局，不继续旧版本进行中的本地存档。

## 平衡回归测试

```bash
npm run simulate -- 20000
```

当前简化压力模型的普通难度结果约为：

- 六角色平均通关率：约 53%
- NPC DAY 30 前死亡率：各角色均低于 20%
- NPC DAY 50 前死亡率：各角色均低于 50%

该脚本用于开发调参，不替代真实玩家数据。
