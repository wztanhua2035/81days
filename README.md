# 八十一天 DAY 81 · v1.3

单人卡牌荒岛生存网页小游戏。无需数据库、无需大模型 API，可直接部署到 Zeabur。本版本把“地点”升级为核心机制，并加入三档难度、动态表现、简单音效和服务器排行榜。

## v1.3 主要玩法

- 12 个海岛地点；未探索地点在地图上显示为“未知”
- 游戏开始时，6 名幸存者随机分布到 12 个地点
- 玩家每天选择一个地点探索，探索结束后当天留在该地点过夜
- NPC 每天也会自行选择地点移动和探索
- 取消“每 5 天强制人物遭遇”
- 每个新的一天开始时，同一地点的幸存者会相遇
- 相遇可选择：躲避 / 交易 / 战斗
- 同地点超过 2 名幸存者时，可先选择交易或战斗对象；躲避失败后会被其中 1 人拦住，只能交易或战斗
- 每个地点拥有专属随机事件，玩家每次从 3 个行动选项中选择
- 生命 / 健康增减有浮动动态提示
- 新的一天拥有 DAY 转场；生命值低于 2 时显示危险警告
- 事件文字逐字显示；道具名称高亮
- 关键操作使用 Web Audio 生成轻量提示音，可随时静音
- 正常难度夜间特别事件默认触发率 70%
- 部分夜间事件具有“地点范围”，只影响事件发生地点内的人物
- 开局可选：容易 / 正常 / 困难
- 游戏结束可用 6—8 字符账号提交服务器排行榜
- 排行榜按“幸存天数 → 得分”排序，只保存前 100 名；同账号只保留更好成绩

## 三档难度

后台的难度参数作为“正常”难度基准：

- **容易**：夜间事件约低 10 个百分点，属性检定 +10%，躲避率提高，健康自然消耗略低，并多 1 份开局食物
- **正常**：默认夜间特别事件 70%，采用后台设置基准
- **困难**：夜间事件约高 10 个百分点，属性检定 -10%，躲避率降低，生命恢复机会减少

## 管理后台

访问：

```text
https://你的域名/admin
```

首次启动默认管理密码：

```text
818181
```

建议部署后立即修改。也可以在**第一次启动前**设置：

```text
ADMIN_PASSWORD=你的初始密码
```

后台可以修改：

- 六位角色姓名
- 正常难度的夜间事件基础概率（默认 70%）
- 全局属性检定修正
- 基础躲避成功率
- 每日健康自然下降概率
- 连续三天健康 ≥2 后的回血概率
- 背包容量
- 每人开局额外食物
- 管理密码

角色姓名刷新游戏页面后更新。难度参数在玩家新开一局时写入存档，不会在一局中途突然改变。

## 排行榜与后台数据持久化

管理设置和排行榜都保存在服务器的数据目录中：

```text
data/
```

Zeabur 重新部署容器时，本地文件系统可能被重建。**正式公开给多人玩时，建议挂载持久化 Volume**，例如 `/data`，并设置环境变量：

```text
ADMIN_DATA_DIR=/data
```

这样以下内容都会长期保留：

- 管理密码
- 后台角色姓名 / 难度设置
- 排行榜前 100 名

玩家个人游戏进度仍保存在各自浏览器的 localStorage 中。

## 本地运行

Node.js 18 或更高版本：

```bash
npm install
npm start
```

访问：

```text
http://localhost:3000
```

后台：

```text
http://localhost:3000/admin
```

## Zeabur 部署

1. 解压 ZIP。
2. 将 `day81` 文件夹内全部文件上传到 GitHub Repository。
3. Zeabur 新建 Project → Deploy New Service → GitHub。
4. 选择仓库。
5. Zeabur 会按 Node.js 项目启动；启动命令为 `npm start`。
6. `server.js` 自动读取 `process.env.PORT` 并监听 `0.0.0.0`。
7. 添加域名后即可访问游戏。
8. 建议挂载 `/data` Volume，并设置 `ADMIN_DATA_DIR=/data`。
9. 访问 `/admin` 修改默认管理密码。

同时提供 `Dockerfile` 作为备用部署方式。

## 说明

排行榜接受客户端提交的最终天数和得分，适合小范围朋友试玩和轻量公开站点。由于核心游戏逻辑在浏览器端运行，它不是严格的竞技防作弊排行榜。
